# 買い物リスト: 保留アイテムの絞り込み表示 設計

## 背景・目的

`買い物リスト/` 画面で、保留中のアイテムを一時的に非表示にして「今すぐ買うべきもの（未購入＋購入済み）」だけを見たい、という要望（`仕事メモ0716.txt`）。データの削除は行わず、表示/非表示のみをトグルする。

## 要件

- 件数表示（`#remainingCount`）の隣に絞り込みボタンを追加する
- ボタン押下で「保留中」のアイテムのみを非表示にする（未購入・購入済みは表示したまま）
- 再度押下すると保留中のアイテムも再表示する
- 絞り込みで非表示にしたアイテムはデータ上削除しない
- 絞り込みON/OFFの状態はlocalStorageに保存し、次回起動時も引き継ぐ

## データ層

- 新しいlocalStorageキー `shoppingFilterHideHeld` に `"1"`（保留を隠す）/ `"0"`（表示）を保存する
- `loadFilterState()`: 値を読み込み、真偽値を返す（未設定時は`false`）
- `saveFilterState(hideHeld)`: 値を保存する

## UI

- `index.html` の `#remainingCount` の直後に以下を追加する

```html
<button type="button" id="toggleHeldButton">保留を隠す</button>
```

- ボタンのラベルは現在のフィルタ状態に応じて「保留を隠す」⇔「保留を表示」に切り替える
- スタイルは既存の `#addStoreButton`（アウトラインボタン）に準じたクラスを `css/style.css` に追加する

## 描画ロジック（`renderList`）

- `renderList()` の先頭でフィルタ状態を読み込む
- アイテムをストアグループ内に描画するループで、フィルタON かつ `item.held === true` の場合はその `<li>` の生成をスキップする（`storeItemList`から除外するのみで、`items`配列自体からは削除しない）
- 件数表示（購入/未購入/保留の件数）は、フィルタ状態に関わらず常に全アイテムを対象に集計する（表示上の絞り込みと実件数を混同しない）

## イベント

- `$("#toggleHeldButton").on("click", ...)` で以下を行う
  1. 現在のフィルタ状態を反転
  2. `saveFilterState()` で保存
  3. ボタンラベルを更新
  4. `renderList(loadItems())` を呼び出して再描画

- `$(document).ready()` 内の初期化時にも、保存済みのフィルタ状態に応じてボタンラベルを初期表示する

## 注意点: 並び替え（`reorderItems`）との整合性

既存の `reorderItems()` は `.storeItemList` 配下の `<li>` をDOMから走査して新しい順序を作り、そのまま `saveItems()` で全件を上書きする。フィルタONで保留アイテムが非表示（DOM上に存在しない）の間にドラッグ&ドロップすると、非表示アイテムがDOMから拾えず保存対象から漏れて**データごと消えてしまう**。これを防ぐため、`reorderItems()` を以下のように修正する。

- DOM走査で得られた表示中アイテムの新順序（`newOrder`）を作った後、フィルタで非表示中の保留アイテムを各ストアの末尾に追加してから `saveItems()` する
- 具体的には、`loadItems()` した全アイテムのうち「フィルタON かつ `held === true`」のものを非表示アイテムとして別途保持し、`newOrder` 構築後に同じ `store` ごとへ追記する

これにより、非表示中に並び替えを行ってもデータが失われず、フィルタOFFに戻したときに元のアイテムがすべて残る（並び順は「表示中アイテム→非表示の保留アイテム」の順になる）。

## 影響範囲・非対象

- 既存の保留トグル・削除・数量変更などの既存機能には影響しない
- 並び替えについては上記の注意点のとおり `reorderItems()` に対応が必要
